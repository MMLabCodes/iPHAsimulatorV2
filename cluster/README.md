# iPHAsimulatorV2 Cluster Installation & GUI GuideThis guide describes the complete workflow for installing and running **iPHAsimulatorV2** on the Swansea University Sunbird cluster.After following this guide you will be able to:- clone the iPHAsimulatorV2 repository- install the scientific simulation environment- install the Streamlit GUI environment- connect to Sunbird using an SSH tunnel- launch the GUI on Sunbird- access the GUI from a browser on your local computer- build and prepare PHA systems- generate OpenMM simulation scripts- submit OpenMM simulations directly to Slurm from the GUI---# 1. Clone the repositoryLog into Sunbird normally for the initial installation:```bashssh username@sunbird.swansea.ac.uk```Replace `username` with your Swansea/Supercomputing Wales username.Move to your scratch directory:```bashcd /scratch/$USER```Clone the repository:```bashgit clone https://github.com/MMLabCodes/iPHAsimulatorV2.git```Enter the repository:```bashcd iPHAsimulatorV2```Confirm the location:```bashpwd```You should be in:```text/scratch/<username>/iPHAsimulatorV2```---# 2. Create the environment storage directoryThe Conda/Mamba environments are stored separately from the repository.Create a working directory:```bashmkdir -p /scratch/$USER/iphasimulator```Set the storage location:```bashexport IPHA_STORAGE="/scratch/$USER/iphasimulator"```Create directories for environments and the Conda package cache:```bashmkdir -p "$IPHA_STORAGE/envs"mkdir -p "$IPHA_STORAGE/conda-pkgs"```Set the Conda package cache:```bashexport CONDA_PKGS_DIRS="$IPHA_STORAGE/conda-pkgs"```The resulting layout will be approximately:```text/scratch/<username>/│├── iPHAsimulatorV2/│└── iphasimulator/    ├── envs/    └── conda-pkgs/```---# 3. Load MambaReset the currently loaded modules:```bashmodule purge```Load Mamba:```bashmodule load mamba/4.14.0-0```---# 4. Install the scientific simulation environmentThe `iphasimulator` environment contains the scientific packages used for building and running simulations.From the repository root:```bashcd /scratch/$USER/iPHAsimulatorV2```Create the environment:```bashmamba env create \    --prefix "$IPHA_STORAGE/envs/iphasimulator" \    -f environment.yml```Activate it:```bashsource activate "$IPHA_STORAGE/envs/iphasimulator"```Confirm which Python is being used:```bashwhich python```It should point to:```text/scratch/<username>/iphasimulator/envs/iphasimulator/bin/python```Check important packages:```bashpython -c "import openmm; print('OpenMM:', openmm.__version__)"python -c "import parmed; print('ParmEd:', parmed.__version__)"python -c "import rdkit; print('RDKit:', rdkit.__version__)"```If these imports succeed, the scientific environment is available.---# 5. Install the GUI environmentThe GUI uses a separate environment called `pha_gui`.Deactivate the scientific environment:```bashsource deactivate```Make sure Mamba is still available:```bashmodule load mamba/4.14.0-0```Create the GUI environment:```bashmamba env create \    --prefix "$IPHA_STORAGE/envs/pha_gui" \    -f environment-gui.yml```Activate it:```bashsource activate "$IPHA_STORAGE/envs/pha_gui"```Confirm the environment:```bashwhich pythonwhich streamlit```These should point to:```text/scratch/<username>/iphasimulator/envs/pha_gui/bin/python/scratch/<username>/iphasimulator/envs/pha_gui/bin/streamlit```Check important GUI packages:```bashpython -c "import streamlit; print('Streamlit:', streamlit.__version__)"python -c "import rdkit; print('RDKit OK')"python -c "import parmed; print('ParmEd OK')"python -c "import py3Dmol; print('py3Dmol OK')"```---# 6. Tell the GUI where the simulation environment livesThe GUI itself runs using `pha_gui`, but scientific operations and simulations use the separate `iphasimulator` environment.Set:```bashexport IPHASIMULATOR_PYTHON="/scratch/$USER/iphasimulator/envs/iphasimulator/bin/python"```Confirm:```bashecho "$IPHASIMULATOR_PYTHON"```You should see:```text/scratch/<username>/iphasimulator/envs/iphasimulator/bin/python```Test the scientific Python directly:```bash"$IPHASIMULATOR_PYTHON" -c \    "import openmm, parmed; print('OpenMM:', openmm.__version__); print('ParmEd:', parmed.__version__)"```If OpenMM and ParmEd versions are printed, the GUI can access the scientific environment.---# 7. Connecting to Sunbird to run the GUIFor normal GUI use, create the SSH tunnel **when you initially connect to Sunbird**.This is important because Sunbird may assign a login session to different login nodes such as `sl1` or `sl2`.On your **local computer**, open a terminal and run:```bashssh -L 8501:localhost:8501 \    username@sunbird.swansea.ac.uk```Replace `username` with your Swansea/Supercomputing Wales username.For example:```bashssh -L 8501:localhost:8501 \    s.983045@sunbird.swansea.ac.uk```Enter your password when requested.This single connection now performs two jobs:1. it logs you into Sunbird2. it forwards port `8501` on your computer to port `8501` on the Sunbird login nodeDo not close this SSH session while using the GUI.You can check which login node you have been assigned:```bashhostname```For example:```textsl1.sunbird.supercomputingwales.ac.uk```or:```textsl2.sunbird.supercomputingwales.ac.uk```Either is fine.---# 8. Prepare the GUI sessionInside the SSH session created in Section 7:```bashcd /scratch/$USER/iPHAsimulatorV2```Confirm:```bashpwd```Reset and load the required modules:```bashmodule purgemodule load mamba/4.14.0-0```Activate the GUI environment:```bashsource activate /scratch/$USER/iphasimulator/envs/pha_gui```Check the executables:```bashwhich pythonwhich streamlit```They should point to the `pha_gui` environment.Now tell the GUI where the scientific Python is:```bashexport IPHASIMULATOR_PYTHON="/scratch/$USER/iphasimulator/envs/iphasimulator/bin/python"```Check it:```bashecho "$IPHASIMULATOR_PYTHON"```Optionally verify the scientific environment:```bash"$IPHASIMULATOR_PYTHON" -c \    "import openmm, parmed; print('OpenMM:', openmm.__version__); print('ParmEd:', parmed.__version__)"```---# 9. Launch StreamlitFrom the root of the repository, with `pha_gui` active:```bashstreamlit run pha_gui.py \    --server.address 127.0.0.1 \    --server.port 8501 \    --server.headless true```A successful launch should produce output similar to:```textUvicorn server started on 127.0.0.1:8501You can now view your Streamlit app in your browser.URL: http://127.0.0.1:8501```Keep this terminal open.Streamlit is now running on the Sunbird login node and the SSH connection is forwarding it to your local computer.You may briefly see messages such as:```textchannel 3: open failed: connect failed: Connection refused```if something on your local computer attempts to access port `8501` before Streamlit has finished starting.If Streamlit subsequently reports that the server has started on `127.0.0.1:8501`, continue to the next step.---# 10. Open the GUIOn your **local computer**, open a web browser and navigate to:```texthttp://localhost:8501```The iPHAsimulatorV2 GUI should appear.The connection is:```textLocal computer      │      │ http://localhost:8501      ▼Local port 8501      │      │ SSH tunnel      ▼Sunbird login node      │      │ 127.0.0.1:8501      ▼Streamlit      │      ▼iPHAsimulatorV2 GUI```---# 11. Important SSH tunnel behaviourAlways create the SSH tunnel as part of the same SSH connection in which Streamlit will be launched:```bashssh -L 8501:localhost:8501 \    username@sunbird.swansea.ac.uk```Then launch Streamlit from inside that session.Avoid starting Streamlit in one SSH session and creating a second independent connection for the tunnel.Sunbird can assign the two connections to different login nodes.For example:```textFirst connection  → sl1 → Streamlit running hereSecond connection → sl2 → SSH tunnel points here```In that situation:```textlocalhost:8501```on `sl2` cannot reach Streamlit running on `sl1`.Creating the tunnel as part of the original login avoids this problem.---# 12. Quick startup procedure for future sessionsOnce iPHAsimulatorV2 and both environments have been installed, Sections 1–6 do **not** need to be repeated every time.For normal day-to-day use, the entire startup procedure is:## On your local computer```bashssh -L 8501:localhost:8501 \    username@sunbird.swansea.ac.uk```## Once connected to Sunbird```bashcd /scratch/$USER/iPHAsimulatorV2module purgemodule load mamba/4.14.0-0source activate /scratch/$USER/iphasimulator/envs/pha_guiexport IPHASIMULATOR_PYTHON="/scratch/$USER/iphasimulator/envs/iphasimulator/bin/python"streamlit run pha_gui.py \    --server.address 127.0.0.1 \    --server.port 8501 \    --server.headless true```## On your local computerOpen:```texthttp://localhost:8501```This is the recommended procedure for launching iPHAsimulatorV2 after the initial installation.---# 13. Running simulations from the GUIOnce the GUI is running, the typical workflow is:1. Build or select a PHA polymer.2. Prepare the molecular system.3. Solvate the system or create the required melt/dry system.4. Register the MD system.5. Open the **OpenMM Workflow Builder**.6. Select the registered MD system.7. Enter a run name.8. Add the required OpenMM workflow steps.9. Generate the OpenMM Python script.10. Inspect the generated script.11. Click **Submit to Slurm**.The GUI submits the generated script through:```textcluster/submit_openmm_job.sh```The Slurm job uses the scientific `iphasimulator` environment rather than the `pha_gui` environment.---# 14. Monitoring Slurm jobsYou can use a second SSH session for monitoring.Log into Sunbird normally:```bashssh username@sunbird.swansea.ac.uk```Check your current jobs:```bashsqueue -u $USER```Useful Slurm states include:```textPD    PendingR     RunningCG    Completing```Cancel a job with:```bashscancel JOBID```---# 15. Monitoring Slurm outputGenerated OpenMM scripts and Slurm submission files are written to:```textmd_simulation_scripts/```Enter that directory:```bashcd /scratch/$USER/iPHAsimulatorV2/md_simulation_scripts```List the newest files:```bashls -lht```Watch standard output:```bashtail -f slurm_<jobname>_<jobid>.out```Watch errors:```bashtail -f slurm_<jobname>_<jobid>.err```To quickly search all Slurm output and error files for failures:```bashgrep -RniE \    "error|exception|traceback|failed|module" \    slurm_*.out slurm_*.err```---# 16. Updating the repositoryBefore pulling changes, move to the repository:```bashcd /scratch/$USER/iPHAsimulatorV2```Check your current branch and working tree:```bashgit status```Pull the appropriate branch.For the main branch:```bashgit pull origin main```For the development branch:```bashgit pull origin dan```If Git reports that local changes would be overwritten, do not force the pull. Commit or stash the local changes first.---# 17. Updating the environmentsEnvironment updates are only necessary when the environment files have changed.Load Mamba:```bashmodule purgemodule load mamba/4.14.0-0```Set the storage location:```bashexport IPHA_STORAGE="/scratch/$USER/iphasimulator"export CONDA_PKGS_DIRS="$IPHA_STORAGE/conda-pkgs"```Update the scientific environment:```bashmamba env update \    --prefix "$IPHA_STORAGE/envs/iphasimulator" \    -f environment.yml```Update the GUI environment:```bashmamba env update \    --prefix "$IPHA_STORAGE/envs/pha_gui" \    -f environment-gui.yml```---# 18. Directory structureA typical installation has the following structure:```text/scratch/<username>/│├── iPHAsimulatorV2/│   ││   ├── cluster/│   │   ├── README.md│   │   ├── submit_openmm_job.sh│   │   └── ...│   ││   ├── structure_database/│   ├── md_simulation_scripts/│   ├── src/│   ├── gui/│   ├── pha_gui.py│   ├── environment.yml│   └── environment-gui.yml│└── iphasimulator/    │    ├── envs/    │   ├── iphasimulator/    │   └── pha_gui/    │    └── conda-pkgs/```---# 19. Environment overviewiPHAsimulatorV2 uses two separate environments on Sunbird:| Environment | Purpose ||---|---|| `iphasimulator` | Scientific environment containing OpenMM, AmberTools, ParmEd, RDKit and simulation dependencies || `pha_gui` | Streamlit GUI environment |When launching the GUI:```textpha_gui   │   ├── runs Streamlit   │   └── knows the location of:             │             ▼       iphasimulator             │             ├── scientific Python             ├── OpenMM             ├── ParmEd             └── simulation dependencies```The connection between the two environments is provided by:```bashexport IPHASIMULATOR_PYTHON="/scratch/$USER/iphasimulator/envs/iphasimulator/bin/python"```Slurm simulations submitted through the GUI are executed using the scientific environment.---# 20. Quick troubleshooting## Browser cannot connectFirst make sure Streamlit is still running.On Sunbird you should see:```textUvicorn server started on 127.0.0.1:8501```The SSH connection used to launch Streamlit must also have been created with:```bashssh -L 8501:localhost:8501 \    username@sunbird.swansea.ac.uk```Do not close this SSH session.---## Check whether Streamlit is runningIn another Sunbird terminal:```bashps -ef | grep streamlit```You can also check whether port `8501` is listening:```bashss -ltn | grep 8501```When running correctly, you should see something listening on:```text127.0.0.1:8501```---## GUI environment is wrongCheck:```bashwhich pythonwhich streamlit```Both should come from:```text/scratch/<username>/iphasimulator/envs/pha_gui/```---## Scientific Python is wrongCheck:```bashecho "$IPHASIMULATOR_PYTHON"```It should point to:```text/scratch/<username>/iphasimulator/envs/iphasimulator/bin/python```Then test:```bash"$IPHASIMULATOR_PYTHON" -c \    "import openmm, parmed; print(openmm.__version__); print(parmed.__version__)"```---## Slurm job was submitted but immediately disappearedCheck the generated `.out` and `.err` files:```bashcd /scratch/$USER/iPHAsimulatorV2/md_simulation_scriptsls -lht slurm_*.out slurm_*.err```Then inspect the newest files:```bashcat "$(ls -t slurm_*.out | head -1)"```and:```bashcat "$(ls -t slurm_*.err | head -1)"```---# 21. Closing the GUIWhen finished using the GUI, return to the terminal running Streamlit and press:```textCtrl+C```This stops the Streamlit server.Then exit Sunbird:```bashexit```Closing the SSH session also closes the SSH tunnel.---# Quick ReferenceFor an already-installed system, the normal startup sequence is:## Local computer```bashssh -L 8501:localhost:8501 \    username@sunbird.swansea.ac.uk```## Sunbird```bashcd /scratch/$USER/iPHAsimulatorV2module purgemodule load mamba/4.14.0-0source activate /scratch/$USER/iphasimulator/envs/pha_guiexport IPHASIMULATOR_PYTHON="/scratch/$USER/iphasimulator/envs/iphasimulator/bin/python"streamlit run pha_gui.py \    --server.address 127.0.0.1 \    --server.port 8501 \    --server.headless true```## Local browser```texthttp://localhost:8501```The GUI can then be used to prepare systems, generate OpenMM workflows and submit simulations directly to Slurm.
